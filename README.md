# BREAKLINE

Браузерный ритм-файтинг. Версия **3.14.0**.

Играть после успешного развёртывания main: https://zhezhe23.github.io/Breakline/?v=3.14.0

Выберите бойца, композицию/арену и режим: дуэль или тренировку. Управление: сенсорный джойстик и три кнопки; на клавиатуре — стрелки, J (рука), K (нога), I (бросок), Esc (пауза). Комбинации — в меню паузы → «Приёмы бойцов».

Для локального запуска откройте index.html в современном браузере или запустите `python3 -m http.server 8000` и откройте http://localhost:8000. Музыка синтезируется локально; для коротких внешних CC0 голосовых эффектов нужен интернет.

## Проверки

Node.js 22+:

```sh
npm ci
npx playwright install chromium
npm run check
npm test
```

Если используется системный Chromium, тест выберет `/usr/bin/chromium`. Можно задать `CHROMIUM_PATH`. `ARTIFACT_DIR=/tmp/breakline-shots npm test` сохраняет скриншоты игровых мобильных размеров.

Тесты покрывают все комбо на 100/120/140 BPM, исходы спецприёмов, фотоэффект, анатомические ограничения, дуэли/ИИ, тренировку, музыкальные часы, паузу, звук, мобильную компоновку и касания. Диагностические функции внедряются только тестовым HTTP-сервером и отсутствуют в релизе.

Диагностика скелета: https://zhezhe23.github.io/Breakline/?v=3.14.0&rig=1

Кинематические ограничения, контроль длины каждого сегмента и отчёты проверок описаны в [KINEMATICS.md](KINEMATICS.md). CI сохраняет отчёт и промежуточные кадры в артефакте `breakline-verification`.

Лаборатория: тренировка → пауза → «Комбо». Выберите рецепт и воспроизведите серию или отдельный следующий удар. Прежние варианты сохранены в режиме «Архив одиночных анимаций»; в обычном бою разнообразие временно отключено. Правила дерева и ошибок — в [COMBOS.md](COMBOS.md).

Новая архитектура и ограничения этапа — в [ANIMATION.md](ANIMATION.md). `npm run render:reel` создаёт прежний контрольный ролик биомеханики; `npm run render:combos` — новый ролик комбо, развилок и ошибочного ввода 1×/0,5×. Оба без аудио; нужен ffmpeg.

Пользователь проверил 3.12.0 на Android. Для 3.14.0 требуется повторная проверка на устройстве. История и ограничения — в CHANGELOG.md; архитектура и оставшиеся этапы — в PROJECT.md.
