# BREAKLINE 3.12.0 — контроль скелета

Длины плеча, предплечья, бедра и голени задаются отдельно для каждого бойца в `RIGS`. Таблицы фиксируются через `Object.freeze`. Анимация изменяет положение таза, ориентацию корпуса и суставные углы.

## Причины дефекта в 3.11.1

- После локального IK отрисовщик применял `scale(scale * facingBlend, scale)`. При развороте X менялся от +1 до −1, Y сохранялся. Измерение реально нарисованных сегментов выявило относительное отклонение до 90,1% у тяжеловеса.
- Прежний тест измерял одну руку в локальных координатах, с другим направляющим вектором, чем использовал отрисовщик. Ноги и итоговое преобразование Canvas оставались без контроля.
- Декартова интерполяция цели кисти могла проходить через плечевой сустав. Выбор ветви IK и смена углового ограничения давали скачки до 180°.
- При переходе к перевёрнутой позе интерполяция двух концов корпуса могла пройти через почти нулевую длину оси. Нормализация после такого прохода резко переворачивала систему координат суставов.

## Текущая цепочка

1. `rigKeys` задаёт положения таза и вращение корпуса. Таз, корпус и конечности получают разные фазы движения согласно профилю бойца. Длина оси корпуса сохраняется; ориентация проходит по дуге.
2. `solveLimb` решает IK ключевых запросов с ограниченной досягаемостью, диапазоном сгиба локтя/колена, диапазоном плеча/таза и постоянным направлением сгиба.
3. `buildFighterSkeleton` интерполирует суставные углы ключей внутри разрешённого диапазона.
4. `forwardLimb` строит сегменты FK:
   - `joint = start + L1 * (cos(upper), sin(upper))`
   - `end = joint + L2 * (cos(lower), sin(lower))`
5. Геометрия, рукава, шорты, накладки, бинты и шлейфы используют узлы полученного скелета. Цель IK за пределами досягаемости не становится координатой нарисованной кисти/стопы.
6. После решения скелета допускаются перенос, вращение, отражение направления и равномерный масштаб. Сжатие по одной оси удалено. Визуальный перенос веса задан профилем и не растёт с дистанцией до противника.
7. Реакция на попадание воздействует на родительский корпус и прикреплённые цепочки. Она не пересчитывает ключевые цели руки через плечо в каждом кадре.

Оценка ритма, `hitAt`, игровые дальности, хитбоксы, урон, комбо, буфер ввода, восстановление и музыкальные часы этим изменением не редактировались.

## Автоматический контроль

`measureFighterSkeleton` проверяет геометрию всех восьми сегментов. Эталон берётся из неизменяемого `RIGS`, а не из метаданных выходной кости. Для каждого сегмента вычисляется `abs(actual / expected - 1)`. Отдельно измеряются реальные углы из векторов костей и направление сгиба; значения не берутся на доверии из метаданных решателя.

Допуск относительной ошибки длины — **1e-6 (0,0001%)**. `auditRigFrame` выполняется для каждого отрисованного бойца после конечной матрицы Canvas. Счётчик `RIG_INTEGRITY` хранит число проверок, максимальную ошибку и сведения о нарушении; нарушение записывается в консоль. Счётчик доступен тестам через их частный fixture, отладочный API в игру не внедрён.

`npm test` автоматически запускает:

- 1 524 сценария четырёх бойцов на 100/120/140 BPM в обоих направлениях;
- 404 116 состояний: сетку 4 мс (250 Гц), кадры 30/60/120 Гц и точки непосредственно до/на/после контакта и окончания действия;
- 3 232 928 измерений сегментов с контролем изменения между соседними кадрами;
- стойки, движение, блок, присед/подъём, прыжок/приземление, направленные и воздушные атаки, все варианты рук/ног, все финалы, спецприёмы, реакции на удар, броски, падения и результат боя;
- сочетания приседа с атакой и попадания с продолжающейся атакой;
- 104 544 измерения сегментов, действительно переданных в `rigLine` после матрицы Canvas, на трёх размерах экрана и DPR 1/2;
- отрицательные контроли: искусственно изменённую кость, старое сжатие X, обратное колено, плечо за разрешённым углом и растянутую кость с подменённой ожидаемой длиной. Все пять должны быть обнаружены;
- существующие 66 сценариев комбо, 60 исходов спецприёмов, полные дуэли с ИИ, ритм/музыку, интерфейс и сенсорное управление.

В текущем локальном измерении максимальная относительная ошибка скелета — `8,9e-16`, изменение между соседними кадрами — `1,5e-15`, экранная ошибка — `3,7e-8` (около **0,000004%**). Экранный допуск учитывает численную точность матриц Canvas. Это измерение центров костей, а не сравнение антиалиасинга растровых пикселей.

## Визуальная проверка

Режим `?v=3.12.0&rig=1` показывает чистые кости с суставами. Эффекты попаданий и аура в нём не перекрывают скелет; ввод, боевой цикл и музыка продолжают работать. Нарушение контроля в этом режиме вызывает явную ошибку.

При `ARTIFACT_DIR=test-artifacts npm test` сохраняются:

- `kinematic-integrity.json` — агрегаты и ошибки по каждому сегменту каждого бойца;
- `skin-intermediate-frames.png` — восемь промежуточных кадров для каждого бойца с обычной геометрией;
- `skeleton-intermediate-frames.png` — те же кадры в режиме костей;
- скриншоты игровых мобильных размеров.

GitHub Actions публикует артефакт `breakline-verification`. В пользовательском workflow `verify` обязателен для `deploy`. Прогон для коммита `a40e717` прошёл успешно: https://github.com/ZheZhe23/Breakline/actions/runs/43014845600.

После публикации проверены все четыре бойца в обычном и скелетном режимах на публичной странице: сенсорные атаки, прыжок с пересечением/разворотом и пауза. Нарушений скелета и исключений JavaScript нет. SHA-256 опубликованного index.html совпадает с локальным.

### Ограничение настройки хостинга

У репозитория также включён старый источник Pages `main` (`build_type: legacy`), который публикуется параллельно и может обходить job `verify`. Попытка переключить на `workflow` через GitHub API получила `403 Resource not accessible by integration`: текущей интеграции не хватает прав. Настройка осталась без изменений.

Владельцу нужно один раз открыть https://github.com/ZheZhe23/Breakline/settings/pages и выбрать **Build and deployment → Source → GitHub Actions**. До переключения проверки CI работают и выявляют регрессии, но старую параллельную публикацию нельзя считать заблокированной ими.

Фактическая проверка на устройстве Android в этой среде не выполнялась.
